在 Windows 10 虚拟机内安装官方最小 MSVC C++ 工具、Windows SDK、Rust MSVC 和 Node，按锁文件安装前端依赖。先扫描新下载的内容并核对签名；不自动运行来源未核对的脚本。代码与测试资料通过项目只读介质交换，不授权宿主个人目录。

Windows 优化构建还需要预装 LLVM `clang-cl` 并加入 PATH；Rust 使用 MSVC 目标，原生 C/C++ 依赖通过 clang-cl 保持 MSVC ABI并映射源码路径。发布前继续检查未压缩程序，路径残留会阻止交付；不要求最终用户安装编译工具。

在 `app/desktop/` 执行：

```powershell
pnpm build:windows -- --arch x64 --version 1.1.0-rc.1 --webview offline
pnpm validate:windows -- --arch x64 --backup C:\ICWB\fixtures\released-schema9-synthetic.icwb --tls C:\ICWB\fixtures\mail-tls
```

`--arch arm64` 用于 ARM64 原生候选。默认打包离线 WebView2 安装器；`--webview installed` 只用于已确认装有 WebView2 的验证环境，不当作离线自包含交付。仅生成当前用户 NSIS 安装包，禁止降级，不索取整机管理员安装权限。输出目录按版本、架构和模式隔离并拒绝覆盖。

构建脚本分别产生普通/Demo 候选，检查未压缩可执行文件是否泄露开发路径（UTF-8 和 UTF-16LE），记录 SHA-256。成功状态是 `built-not-accepted`。自动检查入口默认只接受Win10 21H2/LTSC2021或22H2工作站；显式 `--scope windows` 允许较新的 Windows 工作站或 Server，仍核对并记录真实系统、架构与资源，不能据此声称 Win10 已验收。记录前端、协议、原生 Rust、系统凭据、TLS 正反例及真实 schema9 合成备份迁移，确认实际执行了预期测试且原备份未变；通过也不会将安装与界面检查标成完成。

## 升级与个人数据

同一预览通道保持稳定标识 `com.icengineer.workbench.windowspreview`，Demo 使用 `.demo` 后缀，两者不混用数据库和凭据。后续正式通道若使用不同标识，必须通过显式备份/恢复迁移；不得声称换标识后会自动保留设置和密钥。API/邮箱密钥保存在系统凭据库，不写进备份；换设备或通道需重新配置。

数据库旧 schema 在任何迁移写入前，通过 SQLite Backup API 留存含已提交 WAL 的快照，文件位于应用数据目录的 `migration-backups/`。快照通过版本与完整性检查、同步到磁盘后才开始事务迁移；备份失败阻止迁移，迁移失败回滚；拒绝更新版本数据库和包含未知表的无版本数据库。重新打开当前数据库不重复建立备份。保留历史快照，不自动清理用户恢复点。

安装、升级和卸载必须分别验证：普通版/Demo 隔离；同通道覆盖升级保留资料、主题、会话、草稿和凭据；旧安装器降级阻止；卸载默认保留数据、重装恢复；只有用户明确选择删除个人数据时才清除。SQLite 回归不能替代安装器的这些验证。
